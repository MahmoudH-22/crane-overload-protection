# 16-10-2026

## Built
- Starter repository structure (firmware, app, broker, hardware, mechanical, docs).
- `crane_uno.ino`: full Uno firmware. It covers:
  - sensors with feature flags
  - the safety state machine (overload, near limit, top, jam, link loss, landing, E-stop)
  - soft-start motor control
  - LCD, LEDs and buzzer
  - the checksummed serial protocol
  - EEPROM calibration (TARE / CAL / MAX)
- `crane_nodemcu.ino`: Wi-Fi + MQTT bridge with Last Will, JSON telemetry, events, command whitelist and heartbeat.
- Tools: `i2c_scanner.ino`, `bench_test.ino`; `broker/mosquitto.conf`.
- Flutter app (clean architecture + Riverpod):
  - entities and repository contract
  - MQTT data source, models and settings store
  - dashboard with gauge and controls, and a settings screen with broker, max load and calibration
- Project guide: added the "Implementation A–Z" page with step-by-step build instructions and all code.

## Decided
- Tare from the app only, not at boot (safety).
- Lowering ends on landing detection or a 15 s timeout, since there is no bottom switch.
- The heartbeat only flows while MQTT is connected, so losing the app link stops motion.
- Max load is clamped to the 2.0 kg rated load in both the firmware and the app.
