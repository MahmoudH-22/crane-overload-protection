## Obstacle sensor (ultrasonic under the basket)
- Request: detect anything under the load and stop lowering.
- Decided with the user: block lowering only (LIFT at the top stays blocked by TOP as before); check at every height; stop a lowering at once; clears by itself (no RESET).
- Contract: `crane/live` gains `us` (mm, null if no echo) and `obs` (bool); ack reason `OBSTACLE`; events `OBSTACLE`, `OBSTACLE_CLEARED`.
- Rule (Uno / simulator): obstacle if `us` < `h` − 30 mm (or no echo) while `h` ≥ 50 mm; set after 2 readings, clear after 0.5 s clear.
- Simulator: key `u` toggles an 80 mm object under the basket.
- App: LOWER and downward GO disabled with "Object under the load", held lowering released with STOP, red banner + vibration, "Under the load" card (distance + CLEAR / OBJECT BELOW), event icons.
- Tests: `obstacle_test.dart` (parsing, availability, alert, controller, widgets). `flutter test` 90 passed, analyze clean.
- Live check with the simulator: lowering stopped as soon as the object appeared, LOWER refused with OBSTACLE, cleared 0.5 s after removal, lowering worked again.

## Go to height: tap once
- GO is now a tap-once button: set the height, tap GO, the crane goes there, stops and the card resets. While moving, the button becomes CANCEL (STOP); the red STOP also works.
- Safety: the app sends the GOTO repeats by itself (same 250 ms keep-alive), so the crane still halts within 600 ms if the phone/app dies; every availability rule is re-checked during the move (object below when lowering, overload / load above max / top when lifting, JAM, ESTOP, LOCAL, stale) and a blocked move is stopped with STOP. No contract or firmware change.
- New rule: LIFT and upward GO disabled when `kg` > `max` ("Load above max"), before the crane latches OVERLOAD.
- Tests: 96 passed (tap starts and keeps repeating with no finger, arrival STOP + reset, CANCEL keeps the target, obstacle blocks downward GO, load above max). Live tests not rerun because the user's own broker + simulator were running.
