# 21-11-2026

## Context
- Team asked about dropping the Uno and using only an ESP8266; answered: possible but tight (one ADC for two analog sensors, ~9 safe pins for ~14 needs, 3.3 V logic, Wi-Fi and safety on one chip). Recommendation was to keep the Uno (or use an ESP32).
- Decision: keep the Uno, **replace the NodeMCU Wi-Fi/MQTT bridge with an HC-05 Bluetooth module**. Same Uno pins (D10 / D11 + divider) and the same `crane_link.h` lines, so the Uno sketch logic is unchanged. No laptop, broker or hotspot for the demo.

## Built / changed
- App, connection feature only (telemetry / control / events untouched; they still see topics + JSON):
  - `crane_link_codec.dart`: Dart port of `crane_link.h` (frame / unframe, field checks, L/A/E -> live/ack/events JSON, S -> sensors, command JSON -> `C` line) + `ByteLineSplitter`.
  - `BluetoothGateway` (implements `MqttGateway`): HC-05 link, generated `crane/status` (online while valid lines arrive, offline after 2 s silence, `fw` = `uno-bt`), reconnect back-off 1-15 s, STOP flushed before close on disconnect.
  - `BluetoothPort` / `BluetoothLink` / `PairedDevice` domain interfaces; `FlutterBluePort` adapter on `flutter_blue_classic` 0.1.1 (new package, approved).
  - `TransportGateway`: routes to Bluetooth or MQTT by `BrokerSettings.transport`; MQTT kept for the simulator / desktop.
  - `BrokerSettings`: `transport` (default bluetooth), `btAddress`, `btName`; codegen rerun.
  - Connect screen: Crane (paired-device picker) / Simulator (broker form).
  - Android: Bluetooth permissions (SCAN neverForLocation, CONNECT, legacy <= 30), INTERNET (was missing from the main manifest, so release builds could not reach the broker), minSdk 24.
  - Tests: `bluetooth_link_test.dart` (codec mirrors `link_test.cpp`; gateway with a fake HC-05: lines -> messages, bad checksum, silence -> offline, commands, open failure, reconnect, disconnect), `transport_gateway_test.dart`.
- Firmware: Uno sketch comments / wiring header now describe the HC-05; `crane_link.h` (both copies) points to the Dart port.
- Docs: CLAUDE.md (system, contract notes, serial link, packages, layout, running, key decision, open items), `hardware-bringup.md` and `crane-system-guide.md` rewritten for the HC-05, `app-design.md` updated.

## Hardware session (evening)
- App installed on the vivo V2570 from this laptop. C: was full (70 MB): build temp moved to U:\Temp (`$env:TEMP`), old flutter_tools temp folders, Office download cache (partly) and emulator system images deleted -> 2.8 GB free.
- HC-05 (ZS-040, CSR BC417, firmware 2.0-20100601, address 00:25:07:01:FC:62) blinked fast but no phone / laptop found it.
- Added `firmware/uno/hc05_at_setup/` (AT passthrough, scans 38400 / 9600 / 19200 / 57600, `?` alone rescans). The module only answers while its button is held during each command. First try got no reply: divider wiring (only two 1 k resistors -> 1 k / 1 k divider, 2.5 V on RXD, works).
- Settings found: ROLE 0, IAC 9E8B33, CLASS 1F00. Reset anyway: AT+ORGL, ROLE=0, UART=9600,0,0, NAME=HC-05, PIN 1234. After that the app connected to the crane over Bluetooth.
